## Result

- Metrics with units and evaluation set: LAPA synthetic forward succeeds with
  370,696 parameters and outputs `(4,5,3)` points plus `(4,5)` visibility;
  MV-TAP constructs 30,714,474 parameters; Open-d4rt completes a tiny CPU
  forward with all six output heads; SpaTrackerV2 constructs 65,994,779
  parameters; XFormers CUDA attention succeeds on one RTX A5000.
- Error signature, at most five lines or 500 characters: TrackerSplat package
  metadata generation stops at `CUDA_HOME environment variable is not set`.
  Open3D/InstantSplat stops at `libGL.so.1: cannot open shared object file`.
- Observation (direct evidence only): four projects pass bounded executable
  smokes. TrackerSplat's historical external packages and native modules import,
  but TrackerSplat's own three distinct CUDA extensions are not built. The host
  has no gcc/g++/nvcc/CUDA_HOME, libGL, COLMAP, or FFmpeg executable.

## Interpretation

- Inference: remaining TrackerSplat failures are host-system prerequisites, not
  a Python resolver problem. Its custom featurefusion/motionfusion/KNN APIs
  cannot safely reuse the already compiled Gaussian/Reduced extensions.
- Confidence: high
- Conclusion: LAPA integration and four-project runtime compatibility are
  validated; the five-project goal remains incomplete until the host image is
  rebuilt/provisioned with the required native toolchain and libraries.
- Follow-up ideas: provision build-essential, CUDA 12.4 nvcc, libGL, COLMAP, and
  FFmpeg; then install TrackerSplat with `TORCH_CUDA_ARCH_LIST=8.6` and rerun a
  synthetic kernel/import smoke before any dataset workflow.
