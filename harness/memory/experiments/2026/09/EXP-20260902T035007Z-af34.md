- User request: Install one dependency set for all four submodules into the

## Result

- Metrics with units and evaluation set: `pip check` reports zero broken
  requirements; all protected package versions match the 33-line baseline;
  60+ representative dependencies import; one XFormers CUDA attention kernel
  runs on Torch 2.11.0+cu128; MV-TAP and Open-d4rt help preflights exit 0.
- Error signature, at most five lines or 500 characters: TrackerSplat's
  gaussian-splatting metadata generation raises `CUDA_HOME environment variable
  is not set`; SpaTrackerV2 imports removed `torchvision.io.write_video` (unused
  in that source file).
- Observation (direct evidence only): the shared Python layer is healthy and
  does not change the PyTorch/CUDA stack. TrackerSplat native packages cannot be
  built without nvcc/CUDA_HOME; SpaTrackerV2's remaining imports pass when its
  unused legacy torchvision symbol is bypassed at runtime.

## Interpretation

- Inference: one shared modern Python dependency set is viable. Project-declared
  legacy pins are not a safe install interface; native builds and removed APIs
  must be handled as explicit code/system compatibility work.
- Confidence: high
- Conclusion: shared environment dependency installation successful; two
  non-package prerequisites remain documented rather than forced.
- Follow-up ideas: provide a CUDA 12.8 compiler and initialize TrackerSplat's
  nested submodules before a native-build experiment; separately authorize a
